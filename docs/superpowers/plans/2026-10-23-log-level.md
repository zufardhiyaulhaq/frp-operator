# Log Level and frp v0.71.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `log.level` on Server, Client and ServerPool's `clientTemplate`, an explicit `log.to = "console"` in every rendered config, a Client pod roll that writes the ConfigMap first (fixing the TLS roll), and frp v0.71.1 everywhere.

**Architecture:** One shared API type `LogSpec`. frps gets the level through its rendered TOML, so the existing config hash restarts it. frpc gets it through its ConfigMap plus a pod annotation that triggers the existing roll branch, which is reworked to write the ConfigMap before deleting the pod. ServerPool copies `clientTemplate.log` into generated Clients.

**Tech Stack:** Go 1.23, Kubebuilder v3, controller-runtime v0.18.4, frp v0.71.1 (`fatedier/frpc`, `fatedier/frps`), Docker (`make test-frpc-config`).

**Spec:** `docs/superpowers/specs/2026-10-23-log-level-design.md`

## Global Constraints

- Allowed levels, exactly: `trace`, `debug`, `info`, `warn`, `error`; default `info`.
- Rendered, always, in both `frps.toml` and `frpc.toml`: `log.to = "console"` and `log.level = "<level>"` (`"info"` when unset). Strings via the `quote` template func.
- frp images: `fatedier/frpc:v0.71.1` and `fatedier/frps:v0.71.1` (same release; `TestFrpsImageMatchesFrpcRelease` already pins that).
- An invalid level → `ConfigSynced=False` reason `InvalidConfig` + Warning event; the error text contains `log.level "<value>"`.
- After `api/v1alpha1` changes: `make generate manifests`, then `cat config/crd/bases/frp.zufardhiyaulhaq.com_{clients,upstreams,visitors,serverpools,servers}.yaml > charts/frp-operator/crds/crds.yaml`.
- `pkg/client/utils/template_test.go` mirror structs must gain every field the template uses.
- Commits: `git commit -s`, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Every `docs/superpowers/**/*.md` starts with a Liquid `raw` tag and ends with the matching `endraw` tag.
- `git stash list` holds `log-level: pre-design WIP` (tests and API types written before the design). It may be reused where it matches this plan; drop it once Task 1 is committed (`git stash drop`).

## Review Focus

1. **`log.level: info` set explicitly on an existing Client** must not recreate its pod (same as unset). → `TestReconcile_LogLevelChangeRecreatesPod` (Task 2) asserts it.
2. **The upgrade itself**: a Client whose image *and* config change in one reconcile must start its new pod on the **new** ConfigMap. → `TestReconcile_RollWritesConfigMapFirst` (Task 2) covers the image case too.
3. **The rolled pod must not be hot-reloaded again**: a ConfigMap written during a roll carries no `reload-pending` annotation (the new pod reads it at start). → asserted in `TestReconcile_RollWritesConfigMapFirst`.
4. **An old CRD without the enum** lets `log.level: verbose` through; the operator must report `InvalidConfig` instead of crash-looping frps/frpc. → `TestResolve_LogLevel`, `TestNewConfig_LogLevel`.
5. **Manual Server**: a level change must leave `<server>-frps-config` untouched and report `RestartPending`. → `TestServerReconcile_LogLevelChange` (Task 1).

  - `TestReconcile_LogLevelChangeRecreatesPod`: an existing Pending pod without annotations is **kept** for an unset level **and** for an explicit `log.level: info`; after setting `debug`, it is deleted.
  - `TestReconcile_RollWritesConfigMapFirst`: an existing ConfigMap `<client>-frpc-config` holding stale `config.toml` (no `serverName`) and an existing pod; the Client sets `tls.serverName: frps.example.com` (plus a trusted-CA Secret). A second sub-case does the same with an old image on the pod (`fatedier/frpc:v0.0.1`) and a changed `log.level`.

- [ ] **Step 2: Run them to verify they fail**
  Run: `go test ./pkg/client/... ./controllers/ -run 'LogLevel|TemplateLog|RollWritesConfigMapFirst'`
  Expected: build failure (`Common.LogLevel` undefined); once the model field exists, assertion failures: the pod is kept on `debug`, and the ConfigMap is still stale after the roll.

- [ ] **Step 3: Implement**
  - `NewConfig`: `Common.LogLevel` from `Spec.Log` (empty → `"info"`), reject levels not in `LogLevels` with `errors.NewBadRequest`.
  - `CLIENT_TEMPLATE`: `log.to = "console"` and `log.level = {{ quote .Common.LogLevel }}`, with `"info"` when the field is empty (the mirror structs leave it empty).
  - Controller: set `logLevelAnnotation` on the desired pod when the level is not `info`. Merge the TLS, log and image roll checks into one branch: when any of them differs and the pod is not being deleted, **first** write `configmap.Data` into the existing ConfigMap (drop `reload-pending`), **then** delete the pod; keep the existing events (`PodTLSUpdated`, `PodImageUpdated`, plus a log-level one), status and requeue.
