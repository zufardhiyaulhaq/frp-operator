# E2E tests in GitHub Actions — design

Agreed with the owner in a grilling session on 2026-10-10 (Q1–Q28). This is the source of truth
for `docs/superpowers/plans/2026-10-10-e2e-github-workflow.md`.

## Goal

Prove on every PR that Tier 1 features work end to end: the control plane (Client `Ready` and
`ConfigSynced`, `frp_proxy_status{status="running"}`) **and** real traffic
(test client → frps → frpc → backend → back). Config validity alone is already covered by
`make test-frpc-config`.

## Decisions

| # | Decision |
|---|---|
| Q1 | Both control plane and data path are asserted |
| Q2 | frps runs **inside** the k3d cluster — no public IP anywhere |
| Q3 | Runs on **every PR**: image built in the job, `k3d image import`, nothing pushed |
| Q4 | Go tests, `//go:build e2e`, in `test/e2e/` (client-go + controller-runtime client) |
| Q5 | k3d, one Kubernetes version: k3s `v1.33.7-k3s1` |
| Q6 | Tier 1 first (below); Tier 2 are follow-ups |
| Q7 | Off-the-shelf images: `mendhak/http-https-echo`, `alpine/socat`, `nicolaka/netshoot` (client, via exec) |
| Q9 | One namespace + Client per case, unique remotePort per case, up to 4 cases in parallel; failed namespaces are kept and dumped |
| Q10 | Control plane = Client conditions + operator `/metrics` (`frp_proxy_status` running) |
| Q11 | PR job ≤ 10 minutes |
| Q12 | Operator installed from the repo's Helm chart (tests chart, CRDs, RBAC) |
| Q13 | On failure, upload an artifact: operator / frpc / frps / proxy logs, rendered ConfigMaps, events, Client status |
| Q14 | Replace today's `e2e` job (`sleep 180` + `kubectl get`) in `main.yml`; add the new job to `pullrequest.yml` |
| Q15 | Namespace `frps`: `frps-main` (token; tcp+ws 7000, kcp 7000/udp, quic 7001/udp, vhost HTTP 8080 / HTTPS 8443, tcpmux 5002; server cert, TLS not forced), `frps-mtls` (`trustedCaFile` → forces client certs), `wss-terminator` (nginx `stream`, TLS on 7443 → `frps-main:7000`) |
| Q16 | Certificates (CA, frps server cert, frpc client cert, an unrelated CA) generated by the Go test at startup, stored as Secrets |
| Q17 | frpc dials frps through the Service; the test client reaches remotePorts on the **frps pod IP**; the LoadBalancer `publicAddress` is that pod IP |
| Q18 | Egress proxy: `3proxy` (http + socks5, user/password) + a NetworkPolicy that blocks direct frpc → frps; a probe proves the block, the proxy log is checked |
| Q19 | Reload case: add an Upstream to a running Client → new proxy runs, same pod UID, `restartCount` 0 |
| Q20 | InvalidConfig case: missing Secret key → `ConfigSynced=False/InvalidConfig`, Warning event, `frp_client_config_synced` 0 → add key → recovers |
| Q21 | `make test-e2e` creates its own k3d cluster `frp-operator-e2e`, writes its kubeconfig to a file (never `~/.kube/config`); the suite refuses any context but `k3d-frp-operator-e2e` |
| Q22 | Document that `protocol: wss` needs a TLS terminator in front of frps (CRD description + README) |
| Q23 | Chart value `operator.imagePullPolicy`, default `Always`; e2e uses `IfNotPresent` |
| Q24 | New `e2e` job: install k3d (pinned), buildx `--load linux/amd64` with GHA cache, `make test-e2e` — same target locally and in CI |
| Q25 | One shared `backends` namespace (http echo, TCP echo, UDP echo) |
| Q26 | Single-node k3d |
| Q27 | Explicit poll timeouts; `-count=1`; no automatic re-runs |
| Q28 | One PR for Tier 1 via writing-plans → executing-plans (inline) → code-review; no release for this alone |

## Tier 1 cases

TCP, UDP, `enabled: false`; HTTP vhost (customDomains, locations, request/response headers,
hostHeaderRewrite, basic auth); HTTPS vhost; TCPMUX; STCP + visitor; `protocol` kcp / quic /
websocket / wss; TLS server verification (+ wrong CA rejected); mTLS; egress proxy http + socks5
with `proxyCredentials`; LoadBalancer (ServerPool, TCP + UDP on one port, ingress IP); reload
without pod restart; InvalidConfig → recovery.

## Tier 2 (follow-ups)

XTCP + STCP fallback, cross-user `allowUsers`, OIDC (second frps + mock IdP), plugins,
loadBalancer groups, proxyProtocol.

## Out of scope

Enforcing bandwidth limits and healthCheck timing (config covered by `frpc verify`).
