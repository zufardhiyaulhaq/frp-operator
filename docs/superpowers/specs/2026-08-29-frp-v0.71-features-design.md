# frpc v0.71.0 Upgrade and New Features (v0.9.0)

**Date:** 2026-08-29
**Status:** Approved
**Target release:** frp-operator v0.9.0 / chart 1.7.0

## Background

The operator pins `fatedier/frpc:v0.65.0`. frp v0.66.0 through v0.71.0 added several
client-side features and fixes. Reviewed against the v0.71.0 source
(`pkg/config/v1/{client,proxy,visitor}.go`), the ones that fit the operator's model are:

| frp | Feature | Config key |
|---|---|---|
| v0.66.0 | `loadBalancer` on HTTPS proxies (HTTP already supported it) | `loadBalancer.group`, `loadBalancer.groupKey` on `ProxyBaseConfig` |
| v0.66.0 | Per-proxy / per-visitor enable flag | `enabled` (`*bool`, nil = enabled) |
| v0.67.0 | Client identity in the frps dashboard | top-level `clientID` |
| v0.69.0 | Wire protocol v2 (AEAD-encrypted control channel) | `transport.wireProtocol` = `v1` \| `v2` |

Evaluated and rejected: OIDC `tokenSource` (needs an unsafe flag or a mounted token file, no
demand), frpc `store` (conflicts with the operator being the source of truth), dashboard/API
changes (server-side). `loadBalancer` has no weight in frp — `LoadBalancerConfig` is only
`group` + `groupKey` — so weighted balancing is not possible.

Fixes delivered purely by the image bump, for release notes: UDP proxy-protocol header now sent
only on the first packet of a session (v0.67.0); WebSocket/WSS tunnel frames sent as binary
(v0.70.0); frpc rejects duplicate proxy/visitor names (v0.70.0).

## Goal

Bump frpc to v0.71.0 and expose the four features above. All changes are additive: existing
CRs render byte-identical TOML except for the new `clientID` line.

## Design decisions

1. **`enabled` is a pointer with CRD default `true`.** A missing field and an explicit `true`
   both mean enabled. The template emits `enabled = false` only when disabled, so existing
   configs are unchanged.
2. **Disabled resources release their ports.** A disabled TCP/UDP upstream is skipped by
   `validateUpstreamServerPorts`; a disabled STCP/XTCP visitor is skipped by
   `validateVisitorPorts` and is not added to the Kubernetes Service. This lets users park one
   resource and bring up another on the same port. The disabled proxy/visitor still appears in
   the TOML (with `enabled = false`) so frpc keeps its config.
3. **`clientID` defaults to `<namespace>/<name>` and is overridable.** frps enforces that only one
   client per non-empty `clientID` is online at a time (`server/registry/registry.go`), so the key is
   an identity, not just dashboard metadata. `spec.clientID *string`: nil → automatic
   `<namespace>/<name>`; `""` → the key is omitted (pre-v0.9.0 behavior, no exclusivity); any other
   value → emitted verbatim. *(Amended after final review; originally "not user-settable".)*
4. **`wireProtocol` has no CRD default.** When unset the key is not emitted and frpc's own
   default (`v1`) applies. `v2` requires frps ≥ v0.69.0; documented on the field and in README.
5. **`loadBalancer` reuses the existing types.** `api/v1alpha1.LoadBalancer` and
   `models.LoadBalancerConfig` are reused for HTTP and HTTPS. The `groupKey` secret lookup
   currently inlined in the TCP transform is extracted to a helper shared by all three.
6. **Image tag stays a constant** in `client_controller.go`; making it configurable is out of
   scope. *(Added after code review)* The reconciler now deletes the frpc pod when its container
   image differs from the desired one, so an operator upgrade rolls every client pod once. This
   is required, not optional: frpc starts with `--strict_config=true`, so an old binary that
   restarts against a config containing `clientID` would crash-loop.
7. **Model flag is `Disabled bool`, not `Enabled`.** *(Added after code review)* The zero value
   of a `models.Upstream`/`models.Visitor` literal must be the safe "enabled" state, matching
   frp's own nil-means-enabled `*bool`. The template tests `{{ if $upstream.Disabled }}`.
8. **Duplicate names are validated.** *(Added after code review)* frpc ≥ v0.70.0 rejects configs
   with duplicate proxy/visitor names, and the reconciler matches `spec.client` across all
   namespaces, so `validateUpstreamNames`/`validateVisitorNames` (including the synthetic
   `<name>-fallback` visitor) return a descriptive `BadRequest` before the config is written.
9. **`frpc verify` runs before every reload.** *(Added after code review)* After the ConfigMap is
   confirmed synced into the pod, the operator execs `frpc verify -c /frp/config.toml` (strict
   parsing) and only calls `/api/reload` on success; failures land on the `ConfigSync` condition.

## Changes

### 1. Image bump

- `controllers/client_controller.go`: `SetImage("fatedier/frpc:v0.71.0")`.
- `AGENTS.md` key-constants line.
- Test fixtures that pass `fatedier/frpc:v0.65.0` as an arbitrary string are left alone.

### 2. `enabled` — `Upstream` and `Visitor`

`api/v1alpha1/upstream_types.go`, `UpstreamSpec`; `api/v1alpha1/visitor_types.go`, `VisitorSpec`:

```go
// +optional
// +kubebuilder:default=true
// Enabled controls whether this resource is active in frpc. Set to false to pause it
// without deleting the resource. A disabled resource does not reserve its port.
Enabled *bool `json:"enabled,omitempty"`
```

`pkg/client/models/config.go`:

- `Upstream.Enabled bool` and `Visitor.Enabled bool`, set to `true` unless the spec is
  explicitly `false`.
- `validateUpstreamServerPorts` and `validateVisitorPorts` `continue` on disabled objects.
- New helper `isEnabled(*bool) bool` (nil → true) used by the three sites above.

`controllers/client_controller.go`: the visitor loop that calls `AddVisitorPort` skips disabled
visitors using the same helper.

`pkg/client/utils/template.go`: every `[[proxies]]` and `[[visitors]]` block gains, right after
`type = "..."`:

```
{{ if not $upstream.Enabled }}
enabled = false
{{ end }}
```

(`$visitor.Enabled` in visitor blocks.)

### 3. `clientID` — automatic, overridable

`api/v1alpha1/client_types.go`, `ClientSpec`: `ClientID *string \`json:"clientID,omitempty"\`` (`+optional`).

`pkg/client/models/config.go`: `Common.ClientID string`, set in `NewConfig` to
`clientObject.Namespace + "/" + clientObject.Name`, then overwritten with `*Spec.ClientID` when the
pointer is non-nil (so `""` clears it).

`pkg/client/utils/template.go`, after `serverPort`:

```
{{ if .Common.ClientID }}
clientID = "{{ .Common.ClientID }}"
{{ end }}
```

### 4. `transport.wireProtocol` — `Client`

`api/v1alpha1/client_types.go`, `ClientSpec_Server_Transport`:

```go
// +kubebuilder:validation:Enum=v1;v2
// +optional
// WireProtocol selects the frpc/frps wire protocol. "v2" adds AEAD encryption to the
// control channel and requires frps >= v0.69.0. Defaults to frpc's default ("v1").
WireProtocol string `json:"wireProtocol,omitempty"`
```

`models.TransportConfig.WireProtocol string`, copied in the existing transport transform.

Template, inside the existing transport section:

```
{{ if .Common.Transport.WireProtocol }}
transport.wireProtocol = "{{ .Common.Transport.WireProtocol }}"
{{ end }}
```

### 5. `loadBalancer` — HTTP and HTTPS upstreams

`api/v1alpha1/upstream_types.go`: add to `UpstreamSpec_HTTP` and `UpstreamSpec_HTTPS`:

```go
// +optional
// LoadBalancer groups this upstream with others sharing the same group for load balancing
LoadBalancer *LoadBalancer `json:"loadBalancer,omitempty"`
```

`pkg/client/models/config.go`:

- `Upstream_HTTP.LoadBalancer *LoadBalancerConfig`, `Upstream_HTTPS.LoadBalancer *LoadBalancerConfig`.
- New helper `resolveLoadBalancer(k8sclient, namespace, *frpv1alpha1.LoadBalancer) *LoadBalancerConfig`
  containing the group + secret-backed `groupKey` logic currently inlined in the TCP branch.
  The TCP branch is switched to the helper; behavior (secret missing → empty `GroupKey`) is
  unchanged.

Template: the HTTP and HTTPS proxy blocks gain the same block TCP has:

```
{{ if $upstream.HTTP.LoadBalancer }}
loadBalancer.group = "{{ $upstream.HTTP.LoadBalancer.Group }}"
{{ if $upstream.HTTP.LoadBalancer.GroupKey }}
loadBalancer.groupKey = "{{ $upstream.HTTP.LoadBalancer.GroupKey }}"
{{ end }}
{{ end }}
```

### 6. Generated artifacts, chart, docs

- `make generate manifests`; sync all three CRD documents from `config/crd/bases/` into
  `charts/frp-operator/crds/crds.yaml` (each document replaced wholesale).
- `charts/frp-operator/Chart.yaml`: `version: 1.7.0`, `appVersion: 0.9.0`;
  `values.yaml` `operator.tag: v0.9.0`; `make readme`.
- README feature bullets (via `README.md.gotmpl`): enable/disable flag, wire protocol v2,
  load balancing for HTTP/HTTPS.
- Examples: `examples/http/client/upstream-http.yaml` gains a `loadBalancer` block;
  `examples/tcp-full/client/client.yaml` gains a commented `wireProtocol: v2`;
  `examples/tcp-full/client/upstream.yaml` gains a commented `enabled: false`.
- `docs/releases/v0.9.0.md` in the existing format, including the frps ≥ v0.63.0 compatibility
  note (frp's nine-minor-release policy) and the bump-delivered fixes listed above.

## Testing

TDD throughout; every production change is preceded by a failing test.

- `pkg/client/models/config_test.go`
  - `Enabled`: nil → `true`, `false` → `false`, for Upstream and Visitor.
  - Disabled TCP upstream with a duplicate port does not fail validation; enabled one still does.
  - Disabled visitor with a duplicate port does not fail validation.
  - `Common.ClientID` == `"<ns>/<name>"`.
  - `WireProtocol` copied when set; empty when unset.
  - HTTP and HTTPS `LoadBalancer` resolved, including `groupKey` from a fake-client Secret;
    TCP behavior unchanged after the helper extraction.
- `pkg/client/builder/configuration_builder_test.go`
  - `enabled = false` rendered only for disabled proxies/visitors.
  - `clientID = "…"` rendered.
  - `transport.wireProtocol` rendered only when set.
  - `loadBalancer.*` rendered under HTTP and HTTPS.
- Controller: unit test that `ServiceBuilder` receives no port for a disabled visitor (or, if
  the loop stays inline, a test of the extracted port-collection function).
- `make test`, `make lint`, `helm lint`.
- Manual (orbstack): `make install run`, apply `examples/tcp-full` and `examples/http`, confirm
  frpc v0.71.0 starts, `clientID` appears in the frps dashboard, toggling `enabled: false` reloads
  without a pod restart and the proxy disappears from frps.

## Out of scope

- Weighted load balancing (not supported by frp).
- OIDC `tokenSource`, frpc `store`, configurable frpc image tag.
