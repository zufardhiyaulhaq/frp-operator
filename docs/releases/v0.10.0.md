Releasing v0.10.0 FRP Operator 🥳🥳

Helm chart 1.8.0.

Changes:
1. Prometheus metrics for FRP: `frp_client_info`, `frp_client_ready`, `frp_client_config_synced`, `frp_client_upstreams`, `frp_client_visitors`, `frp_client_admin_up`, `frp_client_last_reconcile_timestamp_seconds`, `frp_proxy_status` (one-hot frpc phase per proxy) and `frp_proxy_info`, read from each frpc's admin API once per reconcile (every 30 s). Series disappear when a `Client` is deleted.
2. Metrics endpoint is plain HTTP on `:8080` by default (`metrics.secure: false`). Set `metrics.secure: true` to keep the previous HTTPS `:8443` endpoint with Kubernetes token authentication.
3. Chart can create a Prometheus Operator `ServiceMonitor` (`metrics.serviceMonitor.enabled`) for the operator; the VictoriaMetrics operator consumes it as well.
4. Grafana dashboard at `dashboards/frp-operator.json` (clients, proxies, operator health, pod resources) — import it into Grafana.

## How to Upgrade

No CRD changes in this release. If your Prometheus already scrapes the operator on `:8443`, either set `metrics.secure: true` or update the scrape config to port `http`/8080.

```yaml
metrics:
  serviceMonitor:
    enabled: true
```
