Releasing v0.11.0 FRP Operator 🥳🥳

Helm chart 1.9.0.

This release adds a LoadBalancer controller: `Service type=LoadBalancer` can now be served by FRP, backed by a new `ServerPool` CRD.

## New CRD: ServerPool

`ServerPool` (namespaced, in the operator namespace) lists the frps servers that LoadBalancer Services can be bound to:

- `servers[]` — `name` (stable key, lowercase, max 40 chars), `host`/`port` (what frpc dials), `publicAddress` (IP or hostname written to the Service status), `authentication`, and optionally `transportProtocol`, `tls`, `transport`, `adminServer` (same shapes as `Client.spec.server`), plus a per-server `allowedPorts` override.
- `allocationPolicy` — `Auto` (default, eligible for any Service) or `Explicit` (only used when a Service names the pool).
- `clientMode` — `PerService` (default, one frpc pod per Service per server) or `Shared` (one frpc pod per server shared by all Services).
- `allowedPorts` — pool-wide list of ports/ranges (`"443"`, `"8000-9000"`) a Service may claim; empty means any.
- `clientTemplate.podTemplate` — applied to every generated `Client`.
- `status.servers[].allocatedPorts` shows current allocations; the `Ready` condition reports validation problems (missing token Secret, duplicate/invalid server name, bad `allowedPorts`).

Apply the new CRD before upgrading the operator (see "How to Upgrade").

## LoadBalancer controller

A `Service` with `type: LoadBalancer` and `loadBalancerClass: frp.zufardhiyaulhaq.com/frp` is bound to one frps server from a `ServerPool`; the operator generates the `Client`/`Upstream` resources in its own namespace and writes the server's `publicAddress` to `status.loadBalancer.ingress`. Existing hand-written `Client`/`Upstream` resources and Services without the class are untouched.

- Annotations: `frp.zufardhiyaulhaq.com/server-pool: <name>` (use only this pool; required for `Explicit` pools) and `frp.zufardhiyaulhaq.com/server: sg-01[,sg-02]` (pin exactly these servers, one IP each, all-or-nothing). The operator records the binding in `frp.zufardhiyaulhaq.com/allocated-server`.
- Selection is deterministic (pools by name, servers in spec order, first server with every port free and allowed) and sticky: a bound Service never moves unless its server disappears from the pool or you edit the annotations. `remotePort` is always the Service port; if it is taken, the Service stays `<pending>` — first come, first served, a running Service never loses its IP.
- The ingress address appears only once the generated frpc client is `Ready` and every proxy reports `running`; IP entries carry `ipMode: Proxy`.
- Events on the Service explain a pending state: `PortUnavailable`, `PortNotAllowed`, `NoServerAvailable`, `ServerNotFound`, `AmbiguousServer`, `PoolNotFound`, `UnsupportedProtocol`, `ClientNotReady`, `ProxyStartError`, `PoolDeleted` (repeated at most every 10 minutes).
- TCP and UDP ports only. A pinned multi-server Service is all-or-nothing: if one pinned server is removed, all its tunnels are torn down until the binding can be satisfied again.
- Uninstalling / disabling: claimed Services carry the finalizer `frp.zufardhiyaulhaq.com/loadbalancer`. Delete claimed Services or drop their `loadBalancerClass` before `helm uninstall` / `loadBalancer.enabled=false`. If the operator is already gone, `kubectl patch svc <name> -p '{"metadata":{"finalizers":null}}' --type=merge` and delete the generated objects (label `frp.zufardhiyaulhaq.com/managed-by=loadbalancer`) yourself.
- Security note: the operator matches `Upstream` to `Client` by name across namespaces, so anyone who can create `Upstream` objects can attach to a generated Client (`pool-<pool>-<server>` / `lb-<ns>-<svc>-<server>`). Restrict `create` on `upstreams.frp.zufardhiyaulhaq.com` to trusted namespaces via RBAC.

See the README "LoadBalancer Controller" section and `examples/loadbalancer/`.

## Other changes

1. New metrics `frp_loadbalancer_service{namespace,service,pool,server,state}` and `frp_serverpool_allocated_ports{pool,server}`, plus a "LoadBalancer" row in the Grafana dashboard. Series for a deleted pool remain until the operator restarts.
2. Chart: `loadBalancer.enabled` (default `true`), `POD_NAMESPACE` env, RBAC for `services/status` and `serverpools`. `make run` sets `POD_NAMESPACE` to `default` for local development.

## How to Upgrade

Helm by default doesn't update the CRDs, you need to apply the CRDs manually:
```
kubectl apply -f https://raw.githubusercontent.com/zufardhiyaulhaq/frp-operator/v0.11.0/charts/frp-operator/crds/crds.yaml
```

If the `ServerPool` CRD is not installed, the operator logs an error and disables the LoadBalancer controller instead of crashing; apply `charts/frp-operator/crds/crds.yaml` and restart the operator to enable it.

Example — a pool with one server and a Service bound to it:
```yaml
apiVersion: frp.zufardhiyaulhaq.com/v1alpha1
kind: ServerPool
metadata:
  name: prod
  namespace: frp-operator
spec:
  servers:
  - name: sg-01
    host: 178.128.100.87
    port: 7000
    publicAddress: 178.128.100.87
    authentication:
      token:
        secret:
          name: sg-01-token
          key: token
---
apiVersion: v1
kind: Service
metadata:
  name: web
  annotations:
    frp.zufardhiyaulhaq.com/server-pool: prod
spec:
  type: LoadBalancer
  loadBalancerClass: frp.zufardhiyaulhaq.com/frp
  selector:
    app: web
  ports:
  - port: 443
    targetPort: 8443
```
