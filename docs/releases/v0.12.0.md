Releasing v0.12.0 FRP Operator 🥳🥳

Helm chart 1.10.0.

This release makes every feature generate a configuration that frpc v0.71.0 accepts, and adds egress-proxy support. Several features rendered keys that frpc rejected outright (so the client never started or never reloaded) or silently dropped settings. Every rendered config is now validated against the real `frpc` binary in CI.

## Fixes: configs frpc rejected

- **Plugins** (`socks5`, `http_proxy`, `static_file`, `unix_domain_socket`, `https2http`, `https2https`, `http2https`, `http2http`): rendered `plugin = "..."`; now `plugin.type = "..."`.
- **XTCP visitors** with the default `enableAssistedAddrs: false`: rendered `natHoleStun.disableAssistedAddrs`; now `natTraversal.disableAssistedAddrs`.
- **`dialServerTimeout` / `dialServerKeepalive`**: rendered as strings (`"15s"`), frpc expects integer seconds. The CRD still takes `"15s"`, `"1m"`, `"-1s"` or whole seconds; the operator converts them.
- **Per-upstream `transport.proxyURL`**: frpc has no such field. See "Breaking changes".
- **Secrets containing `"` or `\`** (tokens, passwords, keys) and **HTTP header names containing `.`** produced an unparseable config; every string is now TOML-escaped and header names are quoted.

## Fixes: settings that were silently ignored

- `spec.server.protocol` (Client) and `transportProtocol` (ServerPool): `kcp`, `quic`, `websocket` and `wss` were stored but never rendered, so frpc always connected over TCP.
- TCPMUX `transport.bandwidthLimit` was not rendered.
- `http_proxy` plugin `httpUser` / `httpPassword` were ignored (only `username` / `password` were read); both are accepted now.
- A missing Secret **key** for the token, STCP/XTCP secret key or visitor secret key returned success with an empty value and dropped **every** upstream and visitor of that Client. Admin, plugin and load-balancer `groupKey` Secrets were ignored when missing. All of these are now reconcile errors (see "Behaviour changes").
- TCP and UDP upstreams on the same server port (e.g. DNS on `53/TCP` + `53/UDP`, including LoadBalancer Services) were rejected as duplicates; frps binds them independently, so they are allowed now.
- `transport.poolCount = 0` was rendered whenever a `transport` block was set.

## New fields

- `Client.spec.server.transport.proxyURL` (also `ServerPool.spec.servers[].transport.proxyURL`): dial frps through an egress proxy — `http://`, `https://`, `socks5://` or `ntlm://`, host and port only.
- `transport.proxyCredentials.{username,password}`: proxy credentials from Secrets, URL-escaped into the proxy URL by the operator.
- With OIDC authentication the token request goes through the same proxy (`auth.oidc.proxyURL`, except `ntlm`, which the OIDC client does not support).
- `Client.spec.user` and `Visitor.spec.{stcp,xtcp}.serverUser`: frp user identity, so STCP/XTCP `allowUsers` can actually be used across clients.
- `Visitor.spec.xtcp.fallback.serverSecretKey`: optional secret for the STCP fallback proxy (defaults to the XTCP secret, as before).

See `examples/egress-proxy/` and `examples/secure-access/stcp-allowusers.yaml`.

## Breaking changes

- `Upstream.spec.<type>.transport.proxyURL` is removed. It never produced a config frpc accepted. Move it to `Client.spec.server.transport.proxyURL` (and credentials to `proxyCredentials`). Existing Upstream manifests that still set it apply with an "unknown field" warning and the field is dropped.

## Behaviour changes

- A referenced Secret or key that does not exist is now a reconcile error (retried with backoff) instead of an empty credential or a default. The last good ConfigMap keeps running meanwhile. Check operator logs for `not found in secret` after upgrading.
- A TCP upstream needs `port` or a `plugin`; previously it dialed port 0.
- `transport.proxyURL` with `protocol: kcp` or `quic` is rejected: frpc dials those over UDP and would bypass the proxy.
- Sub-second dial durations (e.g. `1500ms`) are rejected; frpc only takes whole seconds.

## Other changes

1. `make test-frpc-config` renders every feature, every example and the ServerPool path and validates each file with the deployed `frpc` image (requires Docker); it runs in CI on every PR and on `main`.
2. Every example under `examples/` now applies cleanly and renders a valid config (missing Clients/Secrets added, invalid base64 placeholders and a `maxFaileds` typo fixed).
3. `make test` was not marked `.PHONY`; it now always runs.

## How to Upgrade

Helm by default doesn't update the CRDs, you need to apply the CRDs manually:
```
kubectl apply -f https://raw.githubusercontent.com/zufardhiyaulhaq/frp-operator/v0.12.0/charts/frp-operator/crds/crds.yaml
```

Then upgrade the chart:
```
helm repo update
helm upgrade frp-operator frp-operator/frp-operator --version 1.10.0
```

Example — a Client behind an egress proxy:
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: egress-proxy-credentials
stringData:
  username: "svc-frp"
  password: "p@ss:w/rd"
---
apiVersion: frp.zufardhiyaulhaq.com/v1alpha1
kind: Client
metadata:
  name: egress-client
spec:
  server:
    host: frps.example.com
    port: 7000
    authentication:
      token:
        secret:
          name: frp-token
          key: token
    transport:
      proxyURL: "http://egress-proxy.corp.internal:3128"
      proxyCredentials:
        username:
          secret:
            name: egress-proxy-credentials
            key: username
        password:
          secret:
            name: egress-proxy-credentials
            key: password
```
