Releasing v0.9.0 FRP Operator 🥳🥳

Changes:
1. frpc upgraded from v0.65.0 to v0.71.0. This brings the UDP proxy-protocol fix (header sent only on the first packet of a session), binary WebSocket/WSS tunnel frames, and server-side security fixes — please upgrade frps as well. frpc v0.71.0 is compatible with frps v0.63.0 and newer.
2. `enabled: false` on `Upstream` and `Visitor` to pause a tunnel without deleting the resource. A disabled resource releases its server/visitor port so another resource can take it.
3. `transport.wireProtocol` on `Client` (`v1` | `v2`). `v2` enables an AEAD-encrypted control channel and requires frps >= v0.69.0. Unset keeps frpc's default (`v1`).
4. `loadBalancer` (`group`, `groupKey`) on HTTP and HTTPS `Upstream`, matching TCP (HTTPS load-balancer groups require frps >= v0.66.0).
5. Every `Client` now sets `clientID` (default `"<namespace>/<name>"`, visible in the frps dashboard client list on frps >= v0.67.0). frps allows only one online client per clientID — if you apply the same manifests against one frps from several clusters, set `spec.clientID: ""` to omit it, or give each cluster a distinct value.
6. frpc v0.70.0+ rejects configs with duplicate proxy or visitor names. Rename any `Upstream`/`Visitor` that shares a name with another one referencing the same `Client` (the operator matches on `spec.client` across namespaces).

## How to Upgrade

Helm by default doesn't update the CRDs, you need to apply the CRDs manually:
```
kubectl apply -f https://raw.githubusercontent.com/zufardhiyaulhaq/frp-operator/v0.9.0/charts/frp-operator/crds/crds.yaml
```

The operator creates the frpc pod once and does not roll it on image change. After upgrading the operator, delete the existing client pods so they are recreated with frpc v0.71.0: `kubectl delete pod -l app.kubernetes.io/managed-by=frp-operator -A`. Until then, old pods ignore the new `clientID` and `enabled` keys on reload.

Example — pause an upstream and opt into wire protocol v2:
```yaml
apiVersion: frp.zufardhiyaulhaq.com/v1alpha1
kind: Upstream
spec:
  enabled: false
  ...
---
apiVersion: frp.zufardhiyaulhaq.com/v1alpha1
kind: Client
spec:
  server:
    transport:
      wireProtocol: v2
```
